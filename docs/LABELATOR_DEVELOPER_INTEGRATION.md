# LABELATOR developer integration

.labelator is LABELATOR's portable production template package. This is a general capability. The first production runtime is the Python renderer. A customer integration is a consumer of the package, not a special export mode.

This document matches the in-app page at `/developers`. It does not change the frozen [v1 package contract](./LABELATOR_TEMPLATE_PACKAGE_FORMAT.md).

## Boundary

Design time:

```text
LABELATOR
    ↓
.labelator
```

Production:

```text
external application
    + .labelator
    + production data
    ↓
labelator_renderer
    ↓
PDF
```

LABELATOR does not need to be running during production rendering.

Production rendering does not require LABELATOR, IndexedDB, `data/library.json`, a browser, LABELATOR public assets, a network, or Google Fonts.

## Public API

```python
from labelator_renderer import render

render(
    template_package="warehouse.labelator",
    data=rows,
    output_pdf="labels.pdf",
)
```

## CLI

```text
labelator-render \
    --template warehouse.labelator \
    --data labels.json \
    --output labels.pdf
```

Accepted JSON:

```json
[ { "warehouse_code": "WG6.99.123" } ]
```

```json
{ "rows": [ { "warehouse_code": "WG6.99.123" } ] }
```

## Compatibility

Compatibility is derived by inspecting the document against `PYTHON_RENDERER_PROFILE`. It is not a template id, and it is not a new manifest field.

Designer shows the result when downloading `.labelator` and still downloads the package unless packaging validation fails. The template is not rewritten to become compatible.

Audit every Industrial template without modifying them:

```text
npm run audit:renderer-compatibility
```

## Downloads

```text
LABELATOR
    ↓
.labelator export
    ↓
download / install
    ↓
external application
    ↓
Python renderer
```

Designer export packages the current working document through `buildLabelatorPackage`. It is not a published file.

Templates and `/developers` download published catalog packages from stable static URLs under `/downloads/labelator/`. Those files are generated by:

```text
npm run publish:labelator
```

`npm run build` and `npm run build:pages` run that generator first, then Next copies `public/downloads/labelator/` into the static output. The browser fetches the file. Nothing generates a package on request, and the download does not read IndexedDB, `data/library.json`, or the network.

A valid `.labelator` package can still be incompatible with the current Python renderer. Incompatibility is not a format failure. The published list contains only packages the analyzer accepted.

Regenerate the catalog after a template change. Do not edit the ZIP by hand.

## Not in this capability

No REST API, API keys, OAuth, webhooks, remote rendering, upload endpoint, or template synchronization.
