# LABELATOR developer integration

.labelator is LABELATOR's portable production template package. Design labels in LABELATOR, export them as portable packages, and render them locally with the Python renderer — without running LABELATOR or connecting to the network.

This document matches the in-app page at `/developers`. It does not change the frozen [v1 package contract](./LABELATOR_TEMPLATE_PACKAGE_FORMAT.md).

## Boundary

Design time:

```text
LABELATOR
  ↓
Design / edit template
  ↓
.labelator package
```

Production:

```text
Your application
  + .labelator
  + production data
  ↓
local Python renderer
  ↓
PDF
```

LABELATOR is required for design, not for production rendering.

Production rendering is local. The consuming application owns its data, template storage, and output PDF. The renderer reads the local package and local row data and writes the PDF locally. No LABELATOR runtime or network connection is required.

Production rendering does not require LABELATOR, IndexedDB, `data/library.json`, a browser, LABELATOR public assets, a network, or Google Fonts.

## Install

Current distribution is an editable install from this repository (not a separate registry publish):

```bash
pip install -e tools/labelator_renderer
```

## Public Python API

```python
from labelator_renderer import render

render(
    template_package="Warehouse_A3_Final_v1.labelator",
    data=rows,
    output_pdf="labels.pdf",
)
```

## CLI

```text
labelator-render \
    --template Warehouse_A3_Final_v1.labelator \
    --data labels.json \
    --output labels.pdf
```

The `.labelator` package is the portable template contract for both paths.

Accepted JSON (Warehouse A3 example fields — templates define their own bindings):

```json
[ { "warehouse_code": "WG6.99.123", "barcode": "WG6.99.123" } ]
```

```json
{ "rows": [ { "warehouse_code": "WG6.99.123", "barcode": "WG6.99.123" } ] }
```

## Compatibility

Package validity means the file is a valid `.labelator` v1 package.

Renderer compatibility means a particular renderer supports every capability that package uses.

A valid package can still be incompatible with the current Python renderer. Incompatibility is not a format failure.

Compatibility is derived by inspecting the document against `PYTHON_RENDERER_PROFILE`. It is not a template id, and it is not a new manifest field.

Designer shows the result when downloading `.labelator` and still downloads the package unless packaging validation fails. The template is not rewritten to become compatible.

Audit every Industrial template without modifying them:

```text
npm run audit:renderer-compatibility
```

## Downloads

Designer export packages the current working document through `buildLabelatorPackage`. It is not a published file.

Templates and `/developers` download published catalog packages from stable static URLs under `/downloads/labelator/`. Those files are generated by:

```text
npm run publish:labelator
```

`npm run build` and `npm run build:pages` run that generator first, then Next copies `public/downloads/labelator/` into the static output. The browser fetches the file. Nothing generates a package on request, and the download does not read IndexedDB, `data/library.json`, or the network.

## Not in this capability

No REST API, API keys, OAuth, webhooks, remote rendering, upload endpoint, or template synchronization.
